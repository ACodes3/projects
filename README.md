# Programming Projects

A collection of my software development projects, built through independent learning, university coursework, and hands-on development.

This repository serves as a **software engineering portfolio**, showcasing work across **full-stack development, frontend and backend engineering, databases, DevOps, and desktop applications**. Each project is organized by development area, with its own source code and, where available, documentation covering architecture, setup, and implementation details.

## Selected Full-Stack Projects

### [Demon Slayer Archive](fullstack-projects/demon-slayer-archive/)

A character and world archive developed as a full-stack web application. The project brings together a React frontend, an Express REST API, PostgreSQL, API documentation, input validation, and automated backend tests.

### [Crown of Winter](fullstack-projects/crown-of-winter/)

A multiplayer, fan-inspired strategy application prototype featuring character-based access, PostgreSQL persistence, an interactive War Table, and shared and private real-time communication using Socket.IO.

*Find this project's source and documentation in its corresponding directory once published in this repository.*

## Engineering Focus

The projects in this repository reflect my interests in:

- **Full-stack development:** Connecting user interfaces, REST APIs, and relational databases.
- **Software architecture:** Organizing applications into maintainable components and layers.
- **API development and testing:** Validation, error handling, documentation, and automated tests.
- **Database design:** Relational modeling, constraints, queries, and data integrity.
- **DevOps:** Working with tools such as Docker, Kubernetes, and Vagrant.
- **Desktop software:** Building applications beyond the browser.

The repository includes projects at different stages of development. Individual project READMEs describe their implemented features, setup requirements, and known limitations.

## Getting Started

1. Choose a development category from the table above.
2. Open a project directory to explore the implementation.
3. Read that project's `README.md` for instructions, dependencies, and technical details.
4. Follow any project-specific environment and database setup steps before running the application.

> This is a collection of independent projects, not a single application. Each project may have its own tools, dependencies, and runtime requirements.
